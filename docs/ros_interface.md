# ROS 2 Interface

This document describes the ROS 2 interface exposed by the SpaceWire demonstrator.

The system uses standard ROS 2 Jazzy message and service types. No custom ROS interfaces are required.

# 1. Nodes

During normal operation the following nodes are present.

| Node | Location | Function |
|---|---|---|
| `/spacewire_gateway` | Main BeagleV-Fire | ROS 2 interface to the SpaceWire hardware |
| `/spacewire_gui` | PC | GUI ROS 2 client |
| `/spacewire_diagnostic_aggregator` | PC | Aggregates diagnostic information |

---

# 2. Topics

## `/spacewire/diagnostics`

Type:

```text
diagnostic_msgs/msg/DiagnosticArray
```

Published by:

```text
/spacewire_gateway
```

Contains the current SpaceWire link state, FPGA register values and protocol error status.

Diagnostic information includes:

- started;
- connecting;
- running;
- TX ready;
- TX half full;
- RX valid;
- RX half full;
- disconnect error;
- parity error;
- escape error;
- credit error;
- TX divider;
- raw control register;
- raw status register;
- raw error register;
- SpaceWire core ID.

---

## `/spacewire/camera/image`

Type:

```text
sensor_msgs/msg/Image
```

Published by:

```text
/spacewire_gateway
```

Contains an image received from the mock camera over SpaceWire.

The demonstrator uses:

```text
width:    64
height:   64
encoding: rgb8
step:     192
```

Each image therefore contains:

```text
64 × 64 × 3 = 12288 bytes
```

of RGB image data.

---

## `/spacewire/diagnostics_agg`

Published by:

```text
/spacewire_diagnostic_aggregator
```

Contains the diagnostics after processing by the ROS 2 diagnostic aggregator.

The SpaceWire diagnostic status is grouped under:

```text
/SpaceWire
```

---

## `/spacewire/diagnostics_toplevel_state`

Published by the diagnostic aggregator.

This provides the overall aggregated diagnostic state.

The diagnostic aggregator is used for monitoring only and is not part of the SpaceWire data path.

---

# 3. Services

All control services use:

```text
std_srvs/srv/Trigger
```

## `/spacewire/link/connect`

Requests the main FPGA SpaceWire core to establish the SpaceWire link.

A successful request returns:

```text
success: true
```

after the gateway verifies that the SpaceWire core has reached the running state.

---

## `/spacewire/link/disconnect`

Stops the SpaceWire link.

The gateway verifies the resulting hardware state before returning the service response.

---

## `/spacewire/camera/request_image`

Requests an image from the FPGA mock camera.

The requested image pattern is determined by the gateway's `pattern` parameter.

The service request starts the operation, but the image itself is returned asynchronously on:

```text
/spacewire/camera/image
```

The image is therefore not contained in the service response.

---

# 4. Parameters

## `/spacewire_gateway` — `pattern`

Integer selecting the image generated by the mock camera.

Valid values are:

| Value | Pattern |
|---:|---|
| 0 | Color boxes / grid |
| 1 | Solid red |
| 2 | Solid green |
| 3 | Solid blue |
| 4 | Vertical color bars |
| 5 | Horizontal color bars |
| 6 | Horizontal black-to-white gradient |
| 7 | Vertical black-to-white gradient |

Example:

```bash
ros2 param set /spacewire_gateway pattern 4
```

The selected value is included in the command sent to the FPGA mock camera when an image is requested.

# 5. Example Command-Line Operation

Source ROS 2:

```bash
source /opt/ros/jazzy/setup.bash
```

Check the available nodes:

```bash
ros2 node list
```

Connect the SpaceWire link:

```bash
ros2 service call \
    /spacewire/link/connect \
    std_srvs/srv/Trigger
```

Select an image pattern:

```bash
ros2 param set /spacewire_gateway pattern 4
```

Request an image:

```bash
ros2 service call \
    /spacewire/camera/request_image \
    std_srvs/srv/Trigger
```

Inspect the next received image:

```bash
ros2 topic echo /spacewire/camera/image --once
```

Inspect the SpaceWire status:

```bash
ros2 topic echo /spacewire/diagnostics --once
```

Disconnect:

```bash
ros2 service call \
    /spacewire/link/disconnect \
    std_srvs/srv/Trigger
```

# 6. Launch-Time Remapping

The gateway implementation uses generic internal ROS names. The board launch file remaps these names into the public `/spacewire/...` namespace.

The relevant launch file is:

```text
board/ros2_ws/src/spacewire_gateway/launch/spacewire_gateway.launch.py
```

The public interface is:

```text
/spacewire/diagnostics
/spacewire/camera/image
/spacewire/link/connect
/spacewire/link/disconnect
/spacewire/camera/request_image
```

The PC GUI uses matching remappings from:

```text
pc/ros2_ws/src/spacewire_pc/launch/spacewire_pc.launch.py
```

This keeps the application code independent of the final external namespace.

---

# 7. Communication Between PC and Board

ROS 2/DDS provides communication between the PC and the main BeagleV-Fire over Ethernet.

The typical control path is:

```text
GUI
 │
 │ ROS 2 service / parameter
 ▼
SpaceWire Gateway
 │
 ▼
BeagleV-Fire hardware backend
```

The image path is:

```text
SpaceWire hardware
 │
 ▼
SpaceWire Gateway
 │
 │ sensor_msgs/Image
 ▼
ROS 2 / DDS
 │
 ▼
GUI
```

For the complete hardware and software data flow, see [architecture.md](architecture.md).
